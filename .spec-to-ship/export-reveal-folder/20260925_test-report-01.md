# 测试报告：导出 PDF 后自动打开所在文件夹

日期：2026-09-25

## 改动范围

需求：导出 PDF 后，除顶部「已导出」状态提醒外，自动打开导出文件所在的文件夹（访达中选中该文件），方便后续文件处理。

实现：新增 Tauri 命令 `reveal_in_folder`，导出成功拿到保存路径后由前端尽力调用（失败不影响导出结果与顶部提醒）。PDF 与 Word 导出共用同一导出链路，两者行为一致。

修改文件：

- `apps/desktop/src-tauri/src/exports.rs`：新增 `reveal_target`（校验目标为已存在的文件）与 `reveal_in_folder` 命令；macOS 下经 `NSWorkspace selectFile:inFileViewerRootedAtPath:` 在访达中Reveal文件（阻塞调用放入 `spawn_blocking`，`NSString` 在闭包内构造以满足 `Send`）；新增单元测试 `reveal_requires_an_existing_file`。非 macOS 返回不支持错误。
- `apps/desktop/src-tauri/src/lib.rs`：注册 `exports::reveal_in_folder`。
- `apps/desktop/src-tauri/Cargo.toml`：objc2-app-kit 增加 `NSWorkspace` feature。
- `apps/desktop/src/native/bridge.ts`：`NativeBridge` 增加 `revealInFolder(path)` 及 invoke 实现。
- `apps/desktop/src/native/fakeBridge.ts`：FakeBridge 记录 `revealed`。
- `apps/desktop/src/document/controller.ts`：导出成功且有路径时 fire-and-forget 调用 `revealInFolder`（`.catch(() => {})`，不影响状态提醒）；取消导出（路径为 null）不触发。
- `apps/desktop/src/document/controller.test.ts`：新增 3 个用例——两种格式均按导出路径 reveal、reveal 失败保留成功提醒、取消导出不 reveal。
