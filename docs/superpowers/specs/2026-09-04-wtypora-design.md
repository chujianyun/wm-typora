# WTypora 桌面 Markdown 编辑器设计

## 1. 目标

WTypora 是一个本地优先的桌面 Markdown 编辑器。首版以 macOS 为主要验收平台，同时保持 Windows 和 Linux 可构建。产品体验以 Typora 的核心原则为参照：单栏、低干扰、所见即所得式 Markdown 编辑，而不是源码与预览左右分栏。

首版必须形成完整的本地写作闭环：创建或打开文档、编辑、自动保存、浏览目录、通过大纲导航、查找内容、切换写作模式，以及导出 HTML 或 PDF。

官方功能调研依据：

- [Typora 功能页](https://typora.io/)：实时预览、图片、标题、列表、表格、代码、数学公式、图表、大纲、字数统计、专注模式、打字机模式和导出。
- [Typora 快速入门](https://support.typora.io/Quick-Start/)：Live Preview、文件侧栏、快速打开、大纲、字数统计与主题。
- [Typora Markdown 参考](https://support.typora.io/Markdown-Reference/)：CommonMark/GFM 及 Typora 支持的扩展语法。

## 2. 首版范围

### 2.1 文档与文件

- 新建未命名文档。
- 通过原生对话框打开 `.md`、`.markdown` 和 `.txt` 文件。
- 打开一个目录，并在文件树中展示子目录及受支持的文本文件。
- 保存、另存为和停止输入 800ms 后自动保存。
- 标题栏和状态栏显示当前文件名及保存状态。
- 记录最近打开的文件和目录。
- 监听已打开文件的外部变化并执行冲突处理。
- 关闭未保存文档时提供“保存”“放弃”“取消”。
- 未命名文档及未成功写入磁盘的内容保存为本地恢复草稿。

### 2.2 编辑体验

- 默认使用 Milkdown 提供单栏 WYSIWYM 编辑。
- 支持 CommonMark、GFM、任务列表、表格、围栏代码块、链接、图片、脚注、YAML Front Matter 和 KaTeX 数学公式。
- 使用 CodeMirror 6 提供完整 Markdown 源码模式。
- 两种模式切换时以 Markdown 字符串作为唯一交换格式，磁盘中只保存 Markdown。
- 支持选择文本后的浮动格式工具栏、斜杠插入菜单、撤销和重做。
- 支持文内查找与替换；匹配结果和当前命中项可见。
- 支持字数、字符数、行数、预计阅读时间和光标行列统计。
- 专注模式淡化当前段落之外的内容。
- 打字机模式将当前段落保持在视窗垂直中部。
- 提供浅色、深色和跟随系统三种主题选项。

### 2.3 图片

- 支持拖放和粘贴本地图片。
- 对已有路径的文档，将图片复制到文档同目录的 `<文档名>.assets` 文件夹，并插入相对路径。
- 未命名文档在接收图片前要求用户先保存；用户取消时不修改文档。
- 不自动上传图片，不访问云服务。

### 2.4 Mermaid 图表

- 将语言标识为 `mermaid` 的围栏代码块渲染成 SVG。
- 点击图表后允许查看和编辑原始 Mermaid 文本。
- 语法错误在图表位置显示，并保留全部源码。
- 渲染主题跟随应用主题；HTML 和 PDF 导出包含图表 SVG。
- Mermaid 固定采用 `securityLevel: "strict"`、`startOnLoad: false`，禁用点击回调，并为 `maxTextSize` 与 `maxEdges` 设置有限值。
- 文档内容不能覆盖上述安全配置。严格模式会编码 HTML 并禁用图表点击行为，依据 [Mermaid securityLevel 官方说明](https://mermaid.js.org/config/schema-docs/config-properties-securitylevel.html)。

### 2.5 大纲与导出

- 从文档标题节点即时生成分层大纲。
- 点击大纲条目滚动到对应标题，并高亮当前章节。
- HTML 导出包含当前主题所需 CSS、数学公式样式和 Mermaid 内联 SVG，但不包含可执行脚本。
- PDF 导出使用系统打印对话框，由用户选择打印机或“存储为 PDF”。

## 3. 非目标

首版不包含账户系统、云同步、多人协作、移动端、插件市场、版本控制、全文目录搜索、远程图片上传、DOCX/EPUB 导出、多个窗口或标签页，以及任意 HTML/JavaScript 执行。

文件树首版用于浏览和打开文件；除通过“新建并保存”创建文件外，不提供树内重命名、移动、复制或删除操作。

## 4. 技术架构

### 4.1 技术栈

- Tauri 2：桌面窗口、原生菜单、对话框、文件监听、设置持久化和打包。
- Rust stable，最低 1.77.2：原生文件能力和安全边界。
- React + TypeScript + Vite：应用界面。
- Milkdown/Crepe：默认 Markdown 编辑器。
- CodeMirror 6：源码模式。
- Mermaid：受限 SVG 图表渲染。
- KaTeX：数学公式渲染。
- Zustand：应用与文档会话状态。
- Vitest + Testing Library：前端单元与组件测试。
- Rust 内建测试与临时目录：原生层测试。

### 4.2 模块边界

`AppShell` 只负责窗口布局和全局快捷键；侧栏、标题栏、编辑器、查找面板和状态栏都是独立组件。

`EditorAdapter` 定义编辑器公共接口。Milkdown 和 CodeMirror 分别实现该接口，向文档层报告 Markdown 内容、选区与光标位置。应用业务状态不得依赖任一编辑器的内部节点结构。

`DocumentSession` 是正文状态的唯一拥有者，保存当前路径、Markdown、磁盘基线、脏状态、保存阶段、外部版本和恢复草稿标识。编辑器组件不得直接调用文件 API。

`WorkspaceSession` 保存当前目录、文件树和展开状态。目录扫描只返回支持的文件与目录，并忽略隐藏目录、依赖目录和构建目录。

`NativeBridge` 是前端访问 Rust 命令的唯一入口。它提供打开、读取、原子写入、目录枚举、文件监听和图片复制等带类型的调用，并将原生错误转换为统一的应用错误。

`PreferenceStore` 使用 Tauri Store 保存主题、侧栏状态、编辑模式、最近记录和写作模式设置，不保存正常已落盘文档的正文。

### 4.3 建议目录结构

```text
src/
  app/                 应用壳层、路由式视图状态和快捷键
  components/          标题栏、侧栏、查找面板、状态栏、对话框
  editor/              EditorAdapter、Milkdown、CodeMirror、Mermaid
  document/            DocumentSession、自动保存、冲突与恢复
  workspace/           文件树、大纲和目录会话
  native/              Tauri 调用封装及浏览器测试替身
  export/              HTML 文档生成和打印样式
  preferences/         偏好类型与持久化
  styles/              设计令牌、明暗主题和编辑排版
src-tauri/
  src/commands/        文件、目录、图片和监听命令
  src/error.rs         可序列化原生错误
  capabilities/        最小权限配置
```

## 5. 状态与数据流

### 5.1 文档状态

文档会话至少包含：

```ts
type SaveStatus = "clean" | "dirty" | "saving" | "error";

interface DocumentState {
  path: string | null;
  markdown: string;
  persistedMarkdown: string;
  modifiedAt: number | null;
  saveStatus: SaveStatus;
  saveError: string | null;
  recoveryId: string;
}
```

`saveStatus` 由 `markdown === persistedMarkdown`、进行中的写入和最近错误共同决定。成功写入后才更新 `persistedMarkdown` 与 `modifiedAt`。

### 5.2 打开

用户选择文件后，原生层读取 UTF-8 文本及修改时间。前端创建新的 `DocumentSession`，同步两个编辑器适配器并开始监听该路径。若切换前当前文档为脏状态，必须先完成保存确认流程。

### 5.3 编辑与自动保存

编辑器每次内容变化立即更新内存 Markdown、统计和大纲，并重置 800ms 自动保存计时器。只有拥有路径的文档才自动写入原文件；未命名文档仅更新恢复草稿。手动保存会取消待执行计时器并立即写入。

原子保存流程为：在目标文件所在目录创建唯一临时文件、写入完整 UTF-8 内容、刷新并关闭文件、用重命名替换目标。失败时删除可安全识别的临时文件，保留内存内容与原目标文件，并进入 `error` 状态。

### 5.4 外部修改

文件监听事件触发后，原生层返回最新修改时间和内容摘要：

- 当前会话为 `clean` 时自动载入新内容。
- 当前会话为 `dirty`、`saving` 或 `error` 时显示冲突对话框。
- “重新载入”丢弃内存版本并采用磁盘版本。
- “保留当前版本”不立即覆盖磁盘，先更新外部基线并将状态保持为 `dirty`；下一次显式保存才覆盖。
- 监听器必须忽略由本应用刚完成且摘要一致的保存事件。

### 5.5 模式切换

切换前从当前编辑器获取 Markdown，写入 `DocumentSession`，再将同一 Markdown 设置到目标编辑器。若目标编辑器无法解析某段扩展语法，必须将其保留为源码块而不是静默删除。源码模式是处理未知语法的保真后备路径。

## 6. 界面设计

主窗口采用五区布局：顶部标题栏、左侧侧栏、中央编辑区、临时查找面板和底部状态栏。

- 标题栏包含侧栏开关、文件名、保存状态、源码模式开关和主题入口。
- 侧栏宽度默认 260px，可折叠，在“文件”和“大纲”标签间切换。
- 编辑区正文最大宽度 820px，窗口较窄时保留 24px 内边距。
- 选择文本时出现浮动工具栏；斜杠菜单用于插入块结构，避免永久工具栏占据空间。
- 状态栏展示字数、字符数、行数、预计阅读时间、光标行列和当前编辑模式。
- 专注模式淡化非当前段落；打字机模式只改变滚动定位，不改变文档内容。

键盘命令在 macOS 使用 Command，在 Windows/Linux 使用 Control：新建、打开、保存、另存为、查找、撤销、重做、切换侧栏、切换源码模式、切换专注模式和切换打字机模式。菜单项与快捷键调用同一命令层。

## 7. 安全与隐私

- 应用默认不发起任何网络请求。
- 文件内容、恢复草稿、最近记录和偏好只存放于本机。
- Rust 原生层只允许访问用户通过对话框明确选择的文件、当前工作区，以及应用数据目录。
- 前端 WebView 不获得通配全盘文件权限。
- Markdown 内的原始脚本不执行；导出前移除脚本、事件处理属性、危险 URL 与 iframe。
- Mermaid 只产生严格模式 SVG，禁用交互回调和 HTML 标签。
- 外部链接必须经原生 opener 打开，且仅允许 `http:`、`https:` 和 `mailto:`。

## 8. 错误处理与恢复

Rust 命令统一返回具有 `code`、`message` 和可选 `path` 的错误对象。前端将错误分为可重试通知、需要选择的模态对话框和不可恢复启动错误。

- 打开失败：保留当前文档并显示路径相关错误。
- 保存失败：保留内存内容，保持未保存标记，允许重试或另存为。
- 图片复制失败：不插入失效的 Markdown 链接。
- Mermaid/KaTeX 解析失败：原位显示错误，不影响正文其余部分。
- 设置读取失败：使用默认值启动，并允许在后续保存时重建设置文件。
- 恢复草稿：启动时展示恢复提示；恢复后作为未命名脏文档打开，忽略则删除对应草稿。

## 9. 测试策略

- 对文档状态机覆盖新建、打开、编辑、保存成功、保存失败和外部冲突。

- 对大纲生成、统计、文件过滤、相对图片路径和 HTML 清理使用纯函数单元测试。

- 在临时目录中验证 UTF-8 读取、目录过滤、原子替换和目标文件保留。

- 验证图片复制命名冲突、工作区枚举和修改摘要。
- 验证命令错误可以稳定序列化为前端错误类型。

### 9.3 完成门槛

- 前端单元与组件测试全部通过。
- Rust 测试全部通过。
- TypeScript 类型检查、ESLint 和生产构建无错误。
- Tauri debug 应用可启动并完成新建、保存、重开、图片、Mermaid、源码模式、HTML 导出和系统打印冒烟测试。
- macOS 生产打包成功；Windows/Linux 保持配置与源码兼容，但首版不要求在本机生成对应安装包。

## 10. 环境与交付约束

当前仓库为空且尚无初始提交。实现将从 Tauri 2 + React + TypeScript 工程骨架开始，并保持源文件按职责拆分。

当前机器已安装 Node.js 26.8.1 与 npm/pnpm 11.19.0，但未检测到 `rustc` 或 `cargo`。实现和最终验证需要安装 Rust stable；版本不得低于 Tauri 文件系统插件要求的 1.77.2。

所有新增业务行为按测试驱动流程实现：先写会因缺少行为而失败的测试，再写最小实现并运行完整相关测试。
