# WTypora 完整桌面 Markdown 编辑器重设计

> 状态：设计草案，等待用户最终审批
>
> 日期：2026-09-05
>
> 平台：macOS 首发验收，架构兼容 Windows 与 Linux
>
> 产品目标：成为可以长期替代 Typora 的本地优先 Markdown 桌面编辑器

## 1. 决策摘要

WTypora 从零重做，不恢复也不沿用仓库中旧版实现。产品以技术文档和程序员写作为核心场景，同时保持普通写作的简洁体验。

已确认的不可变设计决策：

- 默认是 Typora 式单一编辑面，不使用常驻的源码/预览双栏。
- Markdown 文本缓冲区是正文的唯一事实来源。
- 即时预览和源码模式是同一编辑器的两种显示状态，共用选区、光标、撤销历史和输入法状态。
- 磁盘上的普通 Markdown 文件是唯一正文存储格式；不引入私有文档容器。
- 不自建账号与云同步，但必须可靠兼容 iCloud Drive、Dropbox、OneDrive、NAS 和 Git 工作区。
- 新窗口默认为无侧栏的专注写作模式，并记住每个窗口最后的界面状态。
- 一份文档对应一个窗口；macOS 可选使用系统原生窗口标签页，不常驻 IDE 式标签栏。
- 核心版不内置 AI、账号、社区或多人协作。
- 交互逻辑、窗口几何和核心工作流尽可能接近 Typora；应用名称、图标、品牌素材、源码和主题资源保持原创。

## 2. 产品原则

### 2.1 文本不可损失

打开、查看、切换显示模式和导出不得修改 Markdown 原文。只有用户编辑或明确执行格式化命令时才能产生正文变更。任何未识别语法均按原文显示和保存。

### 2.2 写作优先

应用启动后第一视觉焦点是正文。侧栏、工具栏、格式标记和辅助信息只在需要时出现，不让为高级用户提供的功能破坏新用户的简洁体验。

### 2.3 本地优先

默认不发起任何网络请求。文档、图片、索引、历史和设置均保存在本地。用户可以使用任意系统同步目录或 Git，而无须让 WTypora 成为数据中介。

### 2.4 原生平台感

macOS 首版必须支持系统菜单、全屏、拼写与语法检查、文件关联、打开方式、标签窗口、服务、分享、打印、标题栏路径和系统外观。Windows 与 Linux 使用同一文档内核与命令模型，只替换平台适配层。

## 3. 完整功能范围

### 3.1 文档编辑

- CommonMark 和 GitHub Flavored Markdown 基础语法。
- 标题、段落、块引用、有序/无序/任务列表、水平线和围栏代码块。
- 粗体、斜体、删除线、行内代码、链接、参考链接、自动链接和图片。
- 表格的键盘编辑、对齐、增删行列、拖动列宽与单元格选择。
- 脚注、YAML Front Matter、TOC、GitHub 式 Callout/Alert、表情符号、高亮、上标和下标。
- 行内和块级 LaTeX 数学公式，错误时保留完整原文。
- Mermaid 作为首个图表引擎；其他图表通过受控扩展接口加入。
- 嵌入式 HTML 可显示安全子集；源码始终可见，脚本永不在编辑界面执行。
- 选中文字后的浮动格式栏、右键菜单、菜单栏命令和可自定义快捷键。
- 文内查找、替换、全部替换、大小写匹配、全词匹配和正则表达式。
- 多光标与列选择放在高级编辑功能中，默认不干扰普通写作。

### 3.2 所见即所得交互

- 光标离开元素时隐藏可安全隐藏的 Markdown 标记，进入元素时局部显示完整原文。
- 正在输入法组字、拖动选区、连续撤销或快速滚动时，装饰层不得重建编辑器或跳动光标。
- 图片、公式、图表和表格是 CodeMirror 范围挂载的可视组件，不持有第二份文档状态。
- 单击可视元素进入编辑，按 `Esc` 退回预览；格式错误就地提示，不以弹窗打断写作。
- 源码模式只切换装饰和编辑规则，不销毁编辑器实例。

### 3.3 文件、工作区与导航

- 新建、打开、保存、另存为、重命名、复制、移动、在 Finder/Explorer 中显示和移至回收站。
- 文件树、文件列表和当前文档大纲三种侧栏视图。
- 侧栏可调宽、固定、折叠，也可作为临时浮层滑入。
- 工作区内新建文件/目录、拖动移动、文件操作撤销、多种排序与目录优先显示。
- 快速打开使用模糊匹配；全局搜索支持正文、路径、标题和 `#tag` 文本匹配。
- 大纲根据标题实时增量更新，支持搜索、层级折叠、自动编号、当前节高亮和键盘导航。
- 最近文件/目录、固定位置、启动时操作和 Dock/任务栏快速入口。
- 工作区文件监听是必选能力；外部创建、删除、重命名和移动要增量反映在侧栏中。

### 3.4 图片与资源

- 支持选择文件、拖放、粘贴剪贴板图片和粘贴图片 URL。
- 可按全局、工作区或 Front Matter 设定保留原路径、复制到相对资源目录或调用外部上传器。
- 支持 `typora-root-url` 等路径基准，但不得修改不相关 Front Matter 字段。
- 图片可对齐、缩放、重命名、移动、复制、下载；批量移动/复制全部图片时使用可预览且可撤销的事务。
- 上传能力通过外部命令或后续受限扩展提供，核心应用不绑定图床。

### 3.5 写作模式与外观

- 专注模式淡化当前行或当前块之外的内容。
- 打字机模式将光标保持在视窗的可配置垂直位置。
- 阅读模式使用只读渲染管线，适用于浏览长文和验证导出效果。
- 浅色、深色和跟随系统外观；内置一组接近 Typora 空间尺度的原创主题。
- 主题是带元数据和版本声明的 CSS 包，支持热重载、错误隔离和导出复用。
- 正文宽度、字号、行高、字体、段落间距和界面缩放可配置。
- 状态栏可隐藏，可选显示字数、字符、行数、阅读时间、当前行列、换行符和文件编码。

### 3.6 导出与发布

- 内建导出 PDF、带主题 HTML、无样式 HTML 和长图/图片。
- 可选调用用户安装的 Pandoc 导出 DOCX、ODT、RTF、EPUB、LaTeX 等格式。
- 导出管线支持目录、主题、数学、图表、脚注、页眉页脚和打印分页规则。
- 记忆每种格式的上次成功设置，支持“使用上次设置导出”与“覆盖上次输出”。
- 导出在独立任务中运行，可取消，错误必须指明阶段、对应源块和可采取的修复动作。

### 3.7 本地历史与恢复

- 正常保存、自动保存与本地历史是三个独立概念。
- 未命名文档和写入失败文档保持可恢复草稿；应用崩溃后必须能识别并恢复。
- 已保存文档可选开启本地快照历史，按数量和时间双重限制清理，不污染工作区。
- macOS 优先接入系统文档版本能力；应用内历史作为跨平台一致保障，二者不相互覆盖。

## 4. 明确非目标

首个完整产品周期不实现：

- 自建账号、付费订阅、云同步和多人实时协作。
- 移动端应用和 Web 版编辑器。
- 内置 AI 改写、问答、翻译或云端语法检查。
- 通用代码 IDE、终端、调试器或 Git 图形客户端。
- 无限权限的第三方 JavaScript 插件市场。
- 对 Typora 品牌资产、图标、主题文件或专有实现的复制。

## 5. 界面与交互规范

### 5.1 窗口骨架

默认窗口从上到下为系统标题栏、中央编辑区和可隐藏状态栏。新窗口不展开侧栏。当用户呼出文件、大纲或搜索时，侧栏从左侧滑入；用户可将其固定为常驻分栏。

正文列默认最大宽度为 760px，在宽屏上水平居中，上下保留充足空间。用户调整正文宽度时，标题、表格、代码块和图片共享同一布局基准，不各自实现一套宽度规则。

### 5.2 窗口与文档

默认一份文档一个窗口。同一文件被再次打开时，激活已有窗口而不创建两个可同时写入的会话。macOS 上 `Command+T` 创建系统原生标签页，Windows/Linux 不为对齐该功能而引入常驻标签栏。

窗口标题显示文件名和未保存状态。在 macOS 上提供标题文件菜单、路径导航和快速重命名；其他平台通过标题右键菜单提供等价命令。

### 5.3 命令模型

所有菜单、快捷键、按钮、右键菜单和命令面板调用同一个命令注册表。每个命令声明唯一 ID、标签、默认快捷键、可用条件、执行函数和撤销语义。不允许组件私自复制“保存”或“切换侧栏”等业务逻辑。

## 6. 技术架构

### 6.1 技术选型

- Tauri 2：桌面运行时、WebView 窗口、菜单、对话框、单实例、深度链接、打印和打包。
- Rust stable：文件事务、监听、索引、搜索、历史、安全边界和平台适配。
- TypeScript + React：应用壳、侧栏、设置、对话框和组件编排。React 不控制每次按键的正文状态。
- CodeMirror 6：唯一文本编辑器与撤销历史。
- Lezer：增量 Markdown 语法树及 WTypora 扩展语法。
- SQLite：工作区索引、搜索元数据、最近记录和本地历史目录；不存储已落盘文档的权威正文。
- KaTeX：交互编辑中的快速数学渲染。
- Mermaid：严格安全配置的图表渲染。
- Pandoc：可选的外部导出后端，不作为启动或基本编辑的必需依赖。

实现计划创建时再锁定已验证的具体版本，本设计不使用 `latest` 作为交付依赖。

### 6.2 模块边界

```text
desktop-shell
  窗口、菜单、快捷键、系统事件、文件关联

document-core (Rust)
  文件会话、原子保存、监听、冲突、草稿、快照历史

workspace-core (Rust)
  文件树、文件操作事务、索引、搜索、最近与固定位置

editor-core (TypeScript)
  CodeMirror 状态、Lezer 扩展、命令、装饰调度、选区映射

editor-widgets (TypeScript)
  表格、图片、数学、图表、代码块、HTML 安全预览

app-shell (React)
  窗口布局、侧栏、查找、快速打开、设置、对话框、通知

render-pipeline
  只读解析、阅读模式、HTML/PDF/图片导出、Pandoc AST

theme-engine
  主题元数据、CSS 令牌、隔离加载、导出样式

platform-adapters
  macOS、Windows、Linux 差异能力
```

每个模块只通过带版本的类型接口交互。`app-shell` 不直接读写文件，`editor-widgets` 不保存权威正文，`workspace-core` 不接触编辑器实例，`render-pipeline` 不反向更新编辑状态。

### 6.3 文档会话模型

```ts
type SavePhase = "clean" | "dirty" | "saving" | "conflict" | "error";

interface DocumentSession {
  id: string;
  path: string | null;
  bufferVersion: number;
  persistedVersion: number;
  persistedHash: string | null;
  diskRevision: { modifiedAtNs: string; size: number; hash: string } | null;
  savePhase: SavePhase;
  lineEnding: "lf" | "crlf";
  encoding: "utf-8" | "utf-8-bom";
  recoveryId: string;
  externalChange: ExternalChange | null;
}
```

Markdown 字符串由 CodeMirror `EditorState` 持有，不在 React Store 内复制一份。`DocumentSession` 只保存版本、磁盘基线和保存阶段。保存请求携带 `bufferVersion` 与完整文本；只有 Rust 返回成功且回传版本匹配时，才更新 `persistedVersion` 和磁盘基线。

## 7. 核心数据流

### 7.1 打开文档

1. 用户通过 Finder、Dock、菜单、快速打开或文件树选择文件。
2. 桌面壳将规范化路径交给 Rust，Rust 验证类型、大小、权限和符号链接边界。
3. Rust 读取原始字节，识别 UTF-8 BOM 和换行符，拒绝不可解码内容而不猜测转码。
4. 创建唯一 CodeMirror 状态和文档会话，建立监听并异步更新索引。
5. 首屏只构建可见范围的装饰和组件；大文档不等待全文图表或公式渲染。

### 7.2 编辑与自动保存

CodeMirror transaction 是正文变更的唯一入口。每次变更增加 `bufferVersion`，更新可见语法装饰、大纲和统计，并重置自动保存计时。

默认停止输入 1,000ms 后自动保存已命名文档。输入法组字期间、对话框尚未决策、已检测外部冲突或前一次写入未完成时不启动新写入。手动保存取消待执行计时器并立即提交最新版本。

原子写入流程：在目标同目录创建带随机后缀的临时文件，以原编码和换行风格写入，刷新文件并关闭，必要时复制权限和可保留元数据，使用平台原子替换。任一步失败都保留原文件与内存内容。

### 7.3 外部修改与同步盘

文件监听事件只是检查信号，不直接被当作新内容。Rust 对文件重新读取并比较哈希、修改时间和文件身份：

- 当前文档干净且外部内容与本应用保存不同：自动重载，保留尽可能接近的光标锚点。
- 当前文档有未保存变更：进入 `conflict`，暂停自动保存，显示“比较、重载磁盘、保留当前并另存为”。
- 路径被外部重命名或移动：能通过文件身份追踪时更新路径；不能确认时转为未定位会话并要求用户选择。
- 文件被删除：保留内存内容，允许原路径重建或另存为。

同步盘可能产生临时空文件、多次重命名和短时不可读状态。监听层对事件短暂合并并以最终可读状态决策，不在第一个删除事件到来时关闭文档。

## 8. 扩展与主题边界

首发先提供稳定主题 API，再开放受限扩展 API。扩展不能直接访问任意文件、网络或应用内部对象。每个扩展必须声明能力，由用户显式启用，并在独立 Worker 或进程中运行。

首批可扩展点限于：代码高亮语言、图表渲染器、图片上传器、导出转换器和命令。扩展对文本的修改必须返回可预览、可撤销的 transaction，不允许在后台静默改写文档。

## 9. 安全、隐私与可访问性

### 9.1 安全与隐私

- 默认禁止网络请求，不嵌入用户行为追踪 SDK。
- 外部链接交给系统浏览器，只允许配置的安全 scheme。
- Markdown HTML 与导出 HTML 使用独立安全策略；编辑界面永不执行文档脚本。
- Mermaid 禁止点击回调、HTML 标签和未经允许的外部资源，并限制文本量、节点数、边数和渲染时间。
- 文件权限以用户选择的文件/目录和应用数据目录为界，符号链接越界需重新授权。
- 诊断日志默认不记录正文、搜索词、完整路径或剪贴板内容。

### 9.2 可访问性

- 全部核心操作可通过键盘完成，焦点顺序稳定且可见。
- 侧栏、大纲、对话框和浮动工具栏具有正确语义和屏幕阅读器标签。
- 主题必须通过文字对比度检查；保存、冲突和错误不只依赖颜色表达。
- 跟随系统的减少动效、增大对比度和输入辅助设置。

## 10. 错误处理

错误格式统一包含 `code`、面向用户的 `message`、可选路径摘要、是否可重试和建议动作。应用将错误分为三类：

- 就地错误：公式、图表、HTML 或链接解析失败，在对应块显示，不影响其他内容。
- 可重试任务：图片复制、索引、导出或外部工具失败，使用非模态任务通知。
- 需要决策的错误：保存失败、外部冲突、未保存关闭或资源批量操作，使用可键盘操作的对话框。

任何错误都不得导致内存正文被空值覆盖、撤销历史被意外清空或原文件被部分写入。

## 11. 性能与稳定性预算

以 macOS Apple Silicon 近五年常见硬件为验收基准，发布版目标为：

- 冷启动到可输入的中位时间不超过 900ms，热启动不超过 450ms。
- 1MB 纯文本 Markdown 打开到首屏可编辑不超过 300ms。
- 普通按键到画面更新的 p95 不超过 16ms，p99 不超过 32ms。
- 100,000 行文档的输入、选择和滚动不冻结主线程超过 100ms。
- 10,000 个 Markdown 文件的工作区首次索引可在后台进行，不阻塞编辑；完成后快速打开结果在 100ms 内返回。
- 闲置时无文档解析或监听风暴时，应用 CPU 持续占用接近 0%。
- 编辑器组件只为可见区域和附近预取区域挂载高成本图表、公式与图片预览。

这些数字是验收预算，不是“尽量”指标。若未达到，对应功能不能标记为完成。

## 12. 测试与验收策略

### 12.1 文本保真金标测试

建立一组真实世界 Markdown corpus，包含 CommonMark/GFM、Typora 扩展、CRLF、BOM、Front Matter、HTML、不完整语法、超长行、Unicode、中日韩文、emoji、组合字符和未知围栏语言。每个样本执行：

1. 读取并打开。
2. 切换即时预览/源码模式多次。
3. 调用阅读和导出管线。
4. 在没有编辑的情况下尝试保存。
5. 断言原始字节完全一致；应用不应该发起实际写入。

### 12.2 编辑器契约测试

- 语法节点与文本范围的映射。
- 装饰显隐前后的光标、选区、拖拽和撤销一致性。
- 中文、日文、韩文输入法组字和候选窗位置。
- 表格、图片、公式、图表和代码块组件产生的每个 transaction 都可撤销且只改变预期范围。
- 粘贴 HTML、富文本、文件、图片和纯文本的优先级和安全规则。
- 大文档可见范围虚拟化与增量解析。

### 12.3 文件系统故障测试

- 磁盘空间不足、只读目录、权限变更、文件被锁定、设备移除和路径过长。
- 原子替换前各阶段注入失败，断言原文件字节不变。
- 同步盘临时删除/重建、连续重命名、外部写入与应用自保存竞争。
- 符号链接越界、目录循环、大量文件事件和工作区索引中断恢复。
- 崩溃、强制结束进程和系统重启后的草稿恢复。

### 12.4 端到端与视觉验收

- macOS 端到端流程：Finder 打开、新建、保存、重命名、标签窗口、拖放图片、外部冲突、恢复、导出和打印。
- 文件树操作：创建、移动、重命名、删除到回收站、撤销和 Finder 双向拖放。
- 键盘工作流：菜单、命令面板、查找替换、快速打开、大纲、格式命令和对话框。
- 浅色、深色、高对比度、不同窗口尺寸、侧栏模式和正文缩放的视觉回归。
- 与受支持的 Typora 交互参考清单逐项人工对比：元素激活、标记显隐、回车/退格、列表继续、表格导航、图片编辑、侧栏和写作模式。

### 12.5 发布门禁

每个可发布构建必须同时满足：

- Rust 单元、属性、故障注入和集成测试全部通过。
- TypeScript 单元、编辑器契约、组件和端到端测试全部通过。
- 文本保真 corpus 字节级对比全部通过。
- 类型检查、格式检查、静态分析、依赖安全审计和生产构建无错误。
- 性能基准没有超出本设计的发布预算。
- macOS Apple Silicon 安装包通过签名、公证、干净机安装和人工验收。
- Windows 与 Linux 至少完成 CI 构建、核心单元测试和文件保真测试，不允许平台适配代码破坏编译。
- 人工验收清单中不存在数据丢失、无法输入、光标跳动、未处理冲突或导出错误等阻断项。

## 13. 交付分解

该产品必须按可独立验收的子项目交付，不以一份超大实施计划一次开发所有功能。

### 阶段 0：工程基线

创建全新 Tauri/Rust/TypeScript 工程、CI、命令模型、窗口壳、可观测性、测试分层和 Markdown corpus。不复制旧版业务源码。

### 阶段 1：文本保真内核

交付唯一 CodeMirror 编辑器、基础 Lezer 扩展、新建/打开/原子保存/恢复、外部冲突和字节级保真测试。此阶段先使用源码显示，不急于引入富组件。

### 阶段 2：Typora 式即时预览

交付标记显隐、块级布局、基础行内格式、列表、链接、图片和代码块，优先验证输入法、光标、选区和撤销稳定性。

### 阶段 3：结构化内容

交付表格、任务列表、数学、图表、Front Matter、脚注、TOC、Callout 和 HTML 安全预览。

### 阶段 4：工作区与大纲

交付文件树/列表/大纲、文件事务、快速打开、全局搜索、最近记录、固定目录与工作区监听。

### 阶段 5：资源、主题与写作模式

交付图片资源策略、批量资源事务、主题引擎、专注模式、打字机模式、阅读模式和可访问性完善。

### 阶段 6：导出与 macOS 产品化

交付 HTML/PDF/图片/Pandoc 导出、打印、系统菜单、标签窗口、服务、分享、拼写检查、签名、公证、升级和完整 macOS 验收。

### 阶段 7：跨平台硬化与受限扩展

完成 Windows/Linux 平台适配、原生安装与冒烟测试，再根据已稳定接口开放图表、图片上传和导出类受限扩展。

## 14. 成功标准

WTypora 达到“可长期替代 Typora”的条件是：

1. 真实 Markdown corpus 在无编辑操作时实现字节级不变。
2. 日常技术文档语法在即时预览中可直接、稳定地编辑，不需要频繁切换源码模式。
3. 比较测试中的核心 Typora 工作流均有等价或更佳实现。
4. 连续使用、崩溃、强制退出、同步盘竞争和磁盘故障测试中不丢失用户正文。
5. 启动、输入延迟、大文档和大工作区指标达到本设计性能预算。
6. macOS 原生工作流、界面几何、侧栏、大纲、写作模式和导出体验通过人工验收。
7. 用户可将现有 Markdown 目录直接交给 WTypora，无需导入、迁移或创建专有库。
